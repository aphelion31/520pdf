# AI tools progress

Implemented consent-gated summarize and translate in `src/ai_tools.rs`. Provider requires `AI_API_URL` (HTTPS), `AI_API_KEY`, and `AI_MODEL`. Each request sends extracted document text to that provider and may incur charges. No live provider requests were made during development.

Options: `consent=true`; translate requires `target_language`; summarize accepts `summary_length=short|medium|long` and `summary_language` (default English). `ocr=true` enables OCRmyPDF with `ocr_language` (default eng). `output_format=txt|pdf` defaults to txt. `bilingual=true` includes original and translation. AI text is limited to 120,000 UTF-8 bytes and provider output to 2 MB. PDF output uses escaped generated UTF-8 HTML and LibreOffice. Translation uses one provider request per nonblank extracted page, at most 20 pages and 2 MB total response. Each translated page starts a new output page, though long translations can flow onto additional pages; layout fidelity is not guaranteed. Runtime dependencies: pdftotext, LibreOffice for PDF, OCRmyPDF and language data for OCR.

Test: `cargo test --test ai_tools` uses an explicitly constructed loopback-only mock provider. Production configuration never enables insecure HTTP. This test checks consent, endpoint policy, escaping and Unicode provider response. Run `cargo test --test ai_tools -- --ignored` in an environment with LibreOffice, pdftotext and Vietnamese/Japanese fonts for the multilingual mock-backed PDF round-trip. It generates a two-page PDF and checks consent, Unicode and page separation. No live provider requests are made. LibreOffice and pdftotext were unavailable locally, so this test was not run here.

Integration: declare `mod ai_tools` and route summarize/translate through `ai_tools::run` in the application. Coordinator verified worker metadata: cx/gpt-6.1-terra, medium effort.
